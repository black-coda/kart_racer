M0: Feasibility spike

Complete

Started: 2026-11-23 · Completed: 2026-11-25

Goal

Prove that the renderer works on the developer’s desktop and on a real Android phone. Do this before the team builds anything that depends on the renderer.

Completed work

  • Created the Serverpod workspace with kart_racer_server, kart_racer_client, and kart_racer_flutter.
  • Ran the starter server and the starter app once. The client connected to the server.
  • Added flutter_scene version 0.24.4 to kart_racer_flutter. The version is an exact pin.
  • Ran the flutter_scene initialization. It added a build hook and an asset directory entry to pubspec.yaml.
  • Enabled Flutter GPU on macOS. The developer added FLTEnableFlutterGPU to macos/Runner/Info.plist.
  • Rendered the built-in cube on macOS. No asset files are necessary for the cube.
  • Added the GLB files type-1.glb (HotRod) and type-2.glb (Toy Car). Both karts show upright and rotate slowly around the Y axis.
  • Recorded the pinned versions and the test devices in the APP.md status tracker.
  • Locked the app to landscape orientation. The phone showed portrait before this change. The lock runs in main() before runApp().
  • Wrote the pinned versions and the run commands into kart_racer_flutter/README.md.
  • Upgraded flutter_scene from 0.24.4 to 0.24.6 and activated serverpod_cli 4.1.2 on 2026-11-25. The developer approved this upgrade.
  • Re-ran the app on macOS after the upgrade. The build succeeds, one kart renders, and the log has no errors. dart analyze and dart format are clean.
  • The developer confirmed the landscape fix on the Pixel 6 on 2026-11-25.
  • Fixed the camera framing on 2026-11-25. Both karts now sit side by side at Y=0 and show in one view. A screenshot on macOS confirms this.
  • Checked the M0 box in the APP.md status tracker on 2026-11-25.

Decisions

  • Pin flutter_scene at an exact version. Hard rule 8 requires an exact pin for this package. The pin moved from 0.24.4 to 0.24.6 on 2026-11-25.
  • Do not pass --enable-impeller to the run command. The flutter_scene README says that Impeller is on by default for native builds since Flutter 3.47.
  • Keep all flutter_scene imports in lib/game/rendering/. cube_view.dart and models_view.dart are the only files that import the package.

Verification

The team ran this command on macOS:

flutter run -d macos --debug
  • The app log shows a pipeline build for PhysicallyBasedMaterial on CuboidGeometry.
  • A screenshot shows a lit cube in the kart_racer window.
  • Both GLB karts stand upright with the wheels on the ground. The karts use the authored scale. The authored bounds are about 0.9 × 0.54 × 1.4 m for type-1 and about 1.19 × 0.28 × 0.49 m for type-2.
  • dart analyze and dart format show no problems for the touched files.
  • The developer confirmed on the Pixel 6 that the cube and both GLB karts render. The screen orientation was wrong. The team fixed it with the landscape lock.
  • After the 0.24.6 upgrade, a screenshot on macOS showed one kart in the frame. The second kart sat above the top edge with the camera and positions committed on 2026-11-24. This framing change was older than the upgrade.
  • After the framing fix, a screenshot on macOS shows both karts in one view: the HotRod on the left and the Toy Car on the right.

Acceptance criteria

  • A cube renders on desktop.
  • A GLB model renders on desktop.
  • A cube and a GLB model render on the Android phone. The developer confirmed this on the Pixel 6.
  • Frame rate on the phone is stable. The developer skipped this test on 2026-11-24.
  • Pinned versions and exact run commands are in kart_racer_flutter/README.md.
  • The M0 box in the APP.md status tracker is checked.
